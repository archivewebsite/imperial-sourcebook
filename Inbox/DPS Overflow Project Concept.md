# Core Identity

This is a text-only clicker and idle battle game.

The player trains two types of damage output:

```txt
Physical DPS
Magical DPS
```

These are not currencies. They are not spent. They are not consumed when attacking monsters.

DPS means damage per second. If the player has 50,000 Physical DPS, they deal 50,000 physical damage per second to physical monsters.

The core progression loop is:

```txt
Train Physical DPS and Magical DPS.
Training-generated DPS creates Level Progress.
Level Progress increases the player’s Level.
Level is used as the requirement for Rebirth.
Rebirth increases future training gains.
Higher DPS defeats stronger monsters.
Monsters give Diamonds.
Diamonds unlock stronger training multipliers, battle equipment, and pets.
The player repeats this forever.
```

Rounds have no final cap. Monster HP continues scaling forever. Monster names may repeat, but their HP and rewards continue increasing.


# Damage and DPS Rule

Physical DPS and Magical DPS are combat power.

They do not decrease during battle.

They are not spent to damage monsters.

They are not spent to level up.

Battle uses DPS to calculate how long it takes to defeat monsters.

Physical monsters use:

```txt
Physical Monster Kill Time = Physical Monster HP / Physical DPS
```

Magical monsters use:

```txt
Magical Monster Kill Time = Magical Monster HP / Magical DPS
```

Example:

```txt
Player Physical DPS = 1,000,000
Physical Monster HP = 5,000,000

Kill Time = 5,000,000 / 1,000,000
Kill Time = 5 seconds
```

If the monster has less HP than the player’s DPS, it dies in under one second.

Example:

```txt
Player Physical DPS = 1,000,000
Physical Monster HP = 250,000

Kill Time = 250,000 / 1,000,000
Kill Time = 0.25 seconds
```

# Training System

The Training system is the source of DPS growth.

The player can train:

```txt
Physical DPS
Magical DPS
```

Each training action gives a random base gain.

Base training gain:

```txt
Random(20, 80)
```

This means each training click generates a random amount between 20 and 80 before multipliers.

# Physical Training Formula

```txt
Physical Training Gain =
Random(20, 80)
× Active Physical Training Multiplier
× Active Physical Battle Equipment Multiplier
× Pet Multiplier
× Rebirth Multiplier
```

Then:

```txt
Physical DPS += Physical Training Gain
Level Progress += Physical Training Gain
```

# Magical Training Formula

```txt
Magical Training Gain =
Random(20, 80)
× Active Magical Training Multiplier
× Active Magical Battle Equipment Multiplier
× Pet Multiplier
× Rebirth Multiplier
```

Then:

```txt
Magical DPS += Magical Training Gain
Level Progress += Magical Training Gain
```

# Critical Training Rule

Training does two things at the same time:

```txt
1. It increases the player’s DPS.
2. It generates Level Progress equal to the DPS gained.
```

Example:

```txt
Physical Training Gain = 50,000

Physical DPS increases by 50,000.
Level Progress also increases by 50,000.
```

The DPS remains permanently available during the current rebirth cycle.

Only Level Progress is consumed by level-ups.

# What Generates Level Progress

Level Progress is generated by new DPS gained from training.

Recommended rule:

```txt
Only newly generated DPS creates Level Progress.
```

This means:

```txt
Training gain creates Level Progress.
Flat DPS rewards, if added later, may create Level Progress once.
Multiplier purchases do not create Level Progress by themselves.
Pets do not create Level Progress by themselves.
Equipment does not create Level Progress by itself.
Rebirth does not create Level Progress by itself.
```

Multipliers only affect future training gains.

Example:

```txt
The player buys a x10 Physical Training Multiplier.

Physical DPS does not instantly increase.
Level Progress does not instantly increase.

The next Physical Training action becomes stronger.
```

This prevents upgrade purchases from creating strange instant level jumps without actual training.

# Level System

The level system is automatic.

The player does not manually buy levels.

The player does not choose when to level up.

The game calculates levels automatically from Level Progress.

The player has:

```txt
Level
Level Progress
Next Level Requirement
```

The Level represents how many level thresholds the player has completed.

Recommended starting state:

```txt
Level = 0
Level Progress = 0
Next Level Requirement = Requirement for Level 1
```

When the player gains enough Level Progress, the game automatically increases the Level.

# Level Overflow Rule

Level Progress can overflow into multiple levels.

Formula:

```txt
Level Progress += Total DPS Output Generated

While Level Progress >= Requirement For Next Level:
    Level Progress -= Requirement For Next Level
    Level += 1
```

Important:

```txt
DPS is not consumed.
Level Progress is consumed.
```

# Level Overflow Example

Suppose:

```txt
Generated DPS = 50,000
```

Level requirements:

```txt
Level 1 Requirement = 1,000
Level 2 Requirement = 5,000
Level 3 Requirement = 10,000
Level 4 Requirement = 17,000
Level 5 Requirement = 26,000
```

Calculation:

```txt
Starting Level Progress = 50,000

Reach Level 1:
50,000 - 1,000 = 49,000 remaining

Reach Level 2:
49,000 - 5,000 = 44,000 remaining

Reach Level 3:
44,000 - 10,000 = 34,000 remaining

Reach Level 4:
34,000 - 17,000 = 17,000 remaining

Level 5 requires 26,000.
17,000 is not enough.

Final Result:
Level = 4
Level Progress toward Level 5 = 17,000
```

The player instantly jumps multiple levels because the generated DPS was high enough.

# Level Requirement Formula

The level system has no cap.

However, Level 1 to Level 1000 should feel like the main structured progression range.

Level 1001 onward should become increasingly difficult.

The early requirements are fixed:

```txt
Level 1 = 1,000
Level 2 = 5,000
Level 3 = 10,000
```

Recommended formula:

```txt
If Level = 1:
Requirement = 1,000

If Level = 2:
Requirement = 5,000

If Level is between 3 and 1000:
Requirement =
floor(10,000 × (Level / 3)^1.85 × 1.0035^(Level - 3))

If Level is greater than 1000:
Requirement =
floor(Level1000Requirement × (Level / 1000)^2.2 × 1.012^(Level - 1000))
```

Where:

```txt
Level1000Requirement = Requirement for Level 1000
```

# Why Level 1001+ Becomes Harder

Before Level 1000, the formula uses moderate scaling.

After Level 1000, the formula uses stronger exponential pressure:

```txt
1.012^(Level - 1000)
```

This means the game can continue forever, but higher rebirths become increasingly expensive in terms of required Level Progress.

# Rebirth System

Rebirth is unlocked through Level.

The player does not rebirth based on round.

The player does not rebirth based directly on current DPS.

The player rebirths when their Level reaches the required level.

Rebirth requirement:

```txt
Required Level for Rebirth N = N × 5
```

Examples:

```txt
Rebirth 1 requires Level 5
Rebirth 2 requires Level 10
Rebirth 3 requires Level 15
Rebirth 4 requires Level 20
Rebirth 5 requires Level 25
Rebirth 10 requires Level 50
Rebirth 100 requires Level 500
Rebirth 200 requires Level 1000
Rebirth 201 requires Level 1005
Rebirth 300 requires Level 1500
Rebirth 400 requires Level 2000
```

This works well with the level formula because Rebirth 200 becomes the point where the player reaches the Level 1000 wall.

After Rebirth 200, rebirth progression becomes much harder naturally.

# Rebirth Preview

Before rebirthing, the game should calculate:


Formula:


# Pets

Pets are purchased with Diamonds.

Pets boost both Physical Training and Magical Training.

Pets affect training gains only.

Recommended formula:

```txt
Pet Multiplier = 1 + Sum of Owned Pet Bonuses
```

Example:

```txt
Pet 1 Bonus = +10%
Pet 2 Bonus = +25%
Pet 3 Bonus = +50%

Total Pet Bonus = 0.10 + 0.25 + 0.50
Total Pet Bonus = 0.85

Pet Multiplier = 1.85x
```

Recommended rule:

```txt
Pet bonuses stack additively, then become one multiplier.
```

Avoid multiplying every pet directly unless you intentionally want very aggressive scaling.

Not recommended:

```txt
1.10 × 1.25 × 1.50
```

Recommended:

```txt
1 + 0.10 + 0.25 + 0.50 = 1.85x
```

# Diamond Reward Formula

Since rounds are infinite, rewards should also scale forever.

Recommended formula:

```txt
Base Diamond Reward =
floor(3 × Round^1.6 × 1.006^Round)
```

Then apply a milestone multiplier.

Milestone multiplier:

```txt
Normal Round = x1
Every 5th Round = x2
Every 10th Round = x5
Every 100th Round = x20
Every 1000th Round = x100
```

Use only the strongest applicable milestone.

Example:

```txt
Round 10 uses x5, not x2.
Round 100 uses x20, not x5 or x2.
Round 1000 uses x100, not x20, x5, or x2.
```

Final formula:

```txt
Diamond Reward =
floor(3 × Round^1.6 × 1.006^Round × Milestone Multiplier)
```

# Main Progression Loop

The complete loop is:

```txt
1. The player trains Physical DPS and Magical DPS.
2. Training generates new DPS.
3. New DPS is added to combat power.
4. The same new DPS is added to Level Progress.
5. Level Progress automatically fills level requirements.
6. Overflow Level Progress carries into future levels.
7. The player reaches the required Level for Rebirth.
8. Auto-Battle uses Physical DPS and Magical DPS to defeat monsters.
9. Clearing rounds gives Diamonds.
10. Diamonds buy stronger training multipliers, battle equipment, and pets.
11. The player rebirths.
12. Rebirth resets DPS, Level, Level Progress, and round progress.
13. Rebirth increases the Rebirth Multiplier.
14. Future training gains become stronger.
15. The player reaches higher levels, higher rebirths, and higher rounds.
```
